# Reproducing this study

These instructions describe the recorded Tower2 experiment and owner-accepted practical installation. The formal3% noninferiority comparison was not qualified, and the owner ended additional qualification and waived the soak. The scripts deliberately pin this host's UUIDs, filesystem locations, model revision and image. Review those contracts before adapting the package to another machine; an adaptation requires its own acceptance evidence.

## Model and runtime

The upstream recipe is [0xSero/deepseek-v4.1-flash-4x-rtx-pro-6000](https://github.com/0xSero/deepseek-v4.1-flash-4x-rtx-pro-6000/tree/45f538a18569420721e00e37353f9a7e1af7e5da), commit `45f538a18569420721e00e37353f9a7e1af7e5da`. Its published four-card performance used 275 W caps and a 128 GB DDR5/NVMe deployment. Its optional full RAM mode was unqualified upstream; this study evaluates that mode on Tower2's 256 GB host. Preserve the upstream MIT license and notice when using its sources.

The checkpoint is [deepseek-ai/DeepSeek-V4.1-Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/tree/fb2764a5cf321eaa5070ca8f9e892818f477c16d), revision `fb2764a5cf321eaa5070ca8f9e892818f477c16d`. The downloaded 88 files total 510,313,345,146 bytes and were fully hash-verified. Startup subsequently checks each recorded file's inode, modification time and byte count against that verification receipt. A copied checkpoint needs a new full verification receipt; do not transplant inode metadata.

The upstream Dockerfile pins `lmsysorg/sglang@sha256:c4ca651192e57e91989b5176c3665148131b9a171e53861dee87f5e57cef25b5`. The actual locally built image used for this study is `sha256:a30e3c69e6a4de1b82e4893dfa971ab94cba126476e3a26f4d1da5d868fae04f`. Rebuilding the same upstream revision does not promise the same local image ID. If the rebuilt image differs, record its identity and qualify it rather than weakening the gate or attributing these results to it.

The adaptation in `runtime/serve-verified-offline-next.py` is installed on this host as `serve-verified-offline.py`. It checks both current-boot fan guards before and after checkpoint metadata verification, disables generation-based periodic health probes before importing SGLang, and starts the RAM sampler. Native settings are RAM offload, TP/EP four, DSpark B5, memory fraction 0.85, chunked prefill 2048, concurrency limit eight, and configured context 409600. The full configured context length is not qualified by the 8k and 65k workloads. The API is bound to host loopback port 8010 and serves `deepseek-v4.1-flash` using a private mode0600 key file. Neither the key nor model weights belong in this publication.

## Measurements and comparisons

One workload trial owns Tower2's native model at a time. Extra model packets, other fan writers, source changes and profile edits are excluded during each timed comparison. The scripts retain exact source/profile/fixture hashes, current boot ID and runtime identity in `result.json`. Preserve that record with the telemetry, request delivery traces and authoritative provider receipts.

Fixtures are constructed by the pinned tokenizer in a CPU-only, network-disabled container. Each request has a unique prefix and exactly 8192 input token IDs; the primary C8 workload generates exactly 2048 output tokens per request. Provider receipts must report the actual usage and zero cached input. Output text is synthetic benchmarking material, not a model quality score. A fresh fixture file is used for every trial.

The comparison protocol uses three matched counterbalanced pairs, in reference/candidate, candidate/reference, reference/candidate order. The original v2 comparison used1200-second runs; it stopped before a third candidate after two third-reference attempts failed the raw closing-slope gate. Their original labels and traces remain retained. The new prospective cycle comparison uses six entirely new1800-second runs plus request drainage, rather than promoting historical results under changed criteria. The reference is protected fixed85%; the candidate uses a byte-identical curve and startup configuration in all its repetitions. The series specification is written before any of its data. Requested and enforced caps must both remain exactly275 W across all four cards.

Original thermal screening checks the last180 seconds for adequate samples and an absolute slope of at most0.3 C/min on every card. Those analyses remain unchanged. Two third-reference attempts showed that cycle timing can affect a narrow closing slope; one also retained a real cooling trend. `v3-temperature-plateau.py` therefore evaluates the new30-minute comparison using the time-weighted means of the last six completely observed C8 workload cycles, spanning170–240 seconds, with the same absolute0.3 C/min limit on every card. Each cycle needs95% telemetry coverage; the last complete cycle may end no more than60 seconds before the final observation. Missing/gapped telemetry, real heating/cooling beyond the limit, nonuniform manual observations, altered caps, raw peaks above82 C and thermal-counter increments still reject qualification. `analysis.json` retains the raw v2 result; `plateau-analysis.json` records the prospective cycle result, original analysis hash and its own pinned source. Eight CPU cases include genuine trends and raw transition peaks, so averaging cannot turn those failures into passes. The separate experimental emergency cutoff remains90 C.

Decode throughput is a core selection criterion. The primary comparative rate uses delivered token increments during intervals when all eight streams are decoding, after their first token and before drainage, within the final600 seconds. The original20-minute protocol provided at least ten minutes of warmup; the new30-minute protocol provides at least twenty. Record the actual common-window coverage, which must be at least300 seconds. This is an observable delivery rate, not GPU-kernel timing. Also retain the final180 rate, whole-run output/elapsed throughput, TTFT and latency distributions, clocks, GPU event counters, paging and model memory. A clock change or isolated slow wave does not establish thermal causality.

For decode and end-to-end throughput separately, the experimental units are the three matched pairs. Compute a two-sided95% Student-t interval on paired log candidate/reference ratios (df2). Both lower bounds must be at least0.97 to support the predeclared no-more-than3% performance-loss claim. Individual requests are not extra independent replications. An uncertain interval is not a pass.

The lower2 prospective30-minute series terminated after its first complete pair: end-to-end ratio0.960035 rules out the declared three-pair gate, and the hottest-card complete-cycle slope independently failed. The original raw analysis passed and remains labeled that way. The subsequent `v2-matched-cycle30-base80` series measures six fresh runs using the original curve and80%/30-second startup; it does not pool the failed pair with the replacement. Its prospective specification SHA256 is `3208d9e69fa6b39752ae9a626969bc46ea03b96c52662afc71b795c225175b31`. See `DECODE.md` for the early-stop bound and its limited interpretation.

The base80 parent series completed two eligible pairs, then stopped before its third candidate when the third reference failed both raw and complete-cycle steadiness. Both middle cards were genuinely cooling at about0.38 C/min; the raw peak was76 C, caps275 and thermal counters unchanged. One entire third-pair replacement was subsequently declared before either new measurement. The amendment retains only the two eligible pairs from this same parent study and repeats reference/candidate with new fixtures, unchanged configuration, boot, sources, windows and gates. It does not import data from the earlier20-minute or lower2 studies. `v2-matched-cycle30-base80-r2-spec.json` SHA256 is `104598321638316d500040f662444dae89c51bd67cbd0f697d0c1067765a1474`; its repetition limit is one. Keep the original failed reference and terminal receipt with the amended comparison, and disclose the thermal-eligibility selection when interpreting the interval. Preparation and execution are separate actions in `v3-repeat-base-third-pair.py`; a prepared specification is not a completed experiment.

The owner selected fan percentage as the relative noise proxy. Use the time-weighted requested and reported mean over the final600 seconds, with at least590 seconds of telemetry coverage, and retain the full-run mean, peak and changes per minute. No dBA or measured inlet-temperature claim is made. Cold startup can lower a full-run mean, so it cannot replace the sustained mean in selection.

Eight NVML target reads are sequential, as are eight fan writes. `coherent_fans.py` brackets each read with fresh primary observations and requires all eight manual targets to match one unchanged declared target. Incoherent reads are retained separately. A nonrenewable250ms retry allowance begins after the first rejected observation; a valid initial NVML query retains the existing five-second sensor bound. Every rejected raw temperature and cap reading still contributes to peak/range analysis. This prevents a serial transition from being silently discarded or mistaken for a persistent nonuniform command.

## Acceptance beyond a screen

The originally planned broader qualification included20-minute C1,65k prefill, final-profile bursts, current-source hot faults, real reboot and a two-hour continuous C8 soak. The owner ended additional testing before those checks completed and explicitly waived the soak. They remain useful optional reproduction steps, not achieved publication claims. The original comparison-gated harnesses retain their strict gates. Separate `v3-*-uncertain.py` orchestration accepts only the exact byte-pinned limited-selection receipt and never calls the comparison qualified. CPU-injected failures prove decisions; process failures prove only the actual tested systemd/hardware paths.

See `OPERATIONS.md` for the exact installation/update, status, automatic restoration and rollback boundary. The permanent writer-lease inode must survive operations. Removing the custom controller leaves caps intact and owned inference paused until a separately reviewed cooling arrangement is ready. Automatic fans reached90 C in about four minutes in the recorded baseline, so automatic fallback is a bounded recovery bridge under that load.

For the design decisions and retained measurement failures, see [ENGINEERING.md](ENGINEERING.md). For a source map, hardware API prerequisites, explicit host contracts and the distinction between the existing-host update bridge and a fresh installation, see [ADAPTATION.md](ADAPTATION.md).

Compact analyses, receipts, source manifests and aggregate tables belong in Git. Full raw traces and delivery/provider records are published as compressed release assets with URL, SHA256 and byte count. Check those hashes before regenerating a figure or comparison, and use the source snapshot for the phase being analyzed.
